# Instrucciones para asistentes de código
Revisar primero `docs/spec.md`. Mantener cambios pequeños y verificables. No publicar secretos ni `data.json`. No modificar contratos de API sin actualizar documentación y pruebas. Priorizar validación de entradas, autorización por usuario y no exponer contraseñas. Explicar limitaciones y no afirmar que se ejecutaron pruebas sin haberlas ejecutado.
